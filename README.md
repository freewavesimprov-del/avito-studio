# Сборщик услуг по гидроизоляционному инъектированию

Москва и Московская область. Результаты — только на компьютере: `results/*.json` и `results/*.csv` (UTF-8 BOM для Excel). Панели, токена и сетевой отправки результатов нет. Исходные логи не включены.

## Быстрый запуск на Mac

Распакуйте весь ZIP в папку. Дважды щёлкните `Установить.command`, дождитесь окончания, затем откройте `Проверить Авито.command`. Это один диагностический запрос; при ошибке осмотрите Chromium и нажмите Enter в терминале. Диагностика лежит в `results/pilot-…/diagnostics`.

Если macOS запрещает открытие .command, выполните команды из раздела ниже в Terminal. Либо из папки проекта: `bash Установить.command`, затем `bash "Проверить Авито.command"`. Установка требует Python 3.9+ и доступа к источникам пакетов и браузера.

После успешного пилота `Собрать объявления.command` запускает полный обход с паузой 15 минут либо продолжает существующий progress.json. Завершённый обход не запускается заново автоматически; для нового исследования используйте другую папку результатов через CLI. Профиль браузера и результаты остаются локально. Одновременно запускайте только один сборщик.

## Установка и запуск

Python 3.9+; команды выполняются в каталоге проекта:

```sh
python3 -m venv .venv &&
.venv/bin/python -m pip install --upgrade pip &&
.venv/bin/python -m pip install -r requirements.txt &&
.venv/bin/python -m playwright install chromium &&
.venv/bin/python collect.py --pages 2
```

Windows: вместо `.venv/bin/python` используйте `.venv\Scripts\python.exe`.
Linux может потребовать системные зависимости Chromium (`playwright install --with-deps chromium` при наличии прав администратора). Для уже установленного Chromium задайте `COLLECTOR_BROWSER` с полным путём к браузеру. В текущем облаке доступен `/usr/bin/chromium`; загрузка браузера Playwright запрещена сетевой политикой.

По умолчанию браузер видимый, запускайте на компьютере с графическим интерфейсом. На машине без дисплея: `COLLECTOR_BROWSER=/usr/bin/chromium .venv/bin/python collect.py --headless --pages 1`. Площадка может ограничивать доступ. Сборщик не решает капчи и не обходит ограничения; ошибки отмечаются в JSON и завершают запуск с кодом 2. Обычный успешный запуск — код 0.

```sh
.venv/bin/python collect.py --repeat 3 --gap 60 --output-dir results
.venv/bin/python -m unittest -v
```

`run-serve.sh` оставлен как обёртка локального запуска для macOS/Linux; режима ожидания заданий больше нет. `--dry` поддержан для совместимости, любой запуск сохраняет данные только локально.

## Настройки и интерпретация

`queries.json`: запросы, регионы, путь категории услуг, режим браузера, сортировка по дате. Категория широкая (`predlozheniya_uslug`), специализация задаётся запросами. Актуальность адреса категории и разметки на живом Авито требует проверки.

Сохраняются исходные цены, текст цены, единица (м², погонный метр, час, выезд либо unspecified), признак «от», продавец, позиция, ссылка. `relevance` — предварительная эвристическая разметка, а не автоматическое исключение: injection, related, equipment_or_materials, uncertain. Проверяйте спорные объявления вручную. Оборудование остаётся в выгрузке с меткой.

Один ID может встречаться в разных запросах и сортировках: это отдельные наблюдения. Внутри одной выдачи повторы между страницами удаляются. Позиции следующих страниц рассчитываются при предположении 50 карточек на страницу. `total` относится к выдаче Авито, а не к числу профильных услуг. Сортировка по дате не гарантирует отсутствие рекламы или непредвзятость; исчезновение объявления не доказывает сделку. Цены разных единиц нельзя объединять в одну медиану. Ценовые диапазоны отключены.

Ошибки страниц (`status: failed/partial`) видны в JSON; пустой CSV при ошибках не означает пустой рынок. Поля и селекторы проверены на локальном HTML, успешный сбор с живого Авито пока не подтверждён: проверка из этого облака завершилась `ERR_TUNNEL_CONNECTION_FAILED`.

Профиль браузера, выгрузки и виртуальное окружение исключены из Git. Репозиторий содержит код; результаты остаются на машине. Не запускайте два процесса с одним профилем браузера.

При HTTP 403/429 или странице «Доступ ограничен» обход немедленно прекращается, уже собранные карточки сохраняются. JSON содержит `stop_reason: access_restricted` и число `queries_not_run` — это не пустые выдачи. Повторных запросов при блокировке нет. Не перезапускайте сбор в цикле: сначала убедитесь вручную, что сайт доступен в обычном браузере; причина ограничения не обязательно связана с VPN.


## Интервалы и продолжение

Между началами запросов выдерживается `--interval` секунд (по умолчанию 900, то есть 15 минут). Это экспериментальная пауза, не известный лимит Авито. Нельзя определить срок блокировки по одному успешному запросу. Автоматических попыток снять ограничение нет.

```sh
.venv/bin/python collect.py --pages 2 --interval 900
```

После каждой успешной страницы атомарно обновляется `results/progress.json`. В нём сохраняются карточки, следующая страница и время последнего обращения. После блокировки либо Ctrl+C продолжите так:

```sh
.venv/bin/python collect.py --pages 2 --interval 1800 --resume
```

При продолжении уже собранные страницы не запрашиваются заново. Интервал отсчитывается от последнего сохранённого обращения, в том числе неудачного. План запросов и `--pages` должны совпадать; интервал разрешено менять. Старые snapshot-файлы не являются checkpoint и не подходят для `--resume`. Результаты длительного обхода получены в разное время, а не одновременно.

Для нового независимого исследования укажите новую папку: `--output-dir results-next`. Существующий checkpoint без `--resume` защищён от перезаписи. Если обход завершён полностью, `--resume` только повторно выгрузит сохранённые данные. При Ctrl+C последние карточки остаются в progress.json, а JSON/CSV snapshot формируется по завершении или при обрабатываемой ошибке.

При 8 запросах, 2 сортировках и 2 страницах потребуется до 32 загрузок: с паузой 15 минут это около 8 часов. Уменьшите список запросов или отключите `collect_by_date` для короткого пилотного замера. Доступ к живому Авито с этими интервалами в облаке не проверен.

## Короткий пилот и диагностика

Для сравнения с обычным браузером, без полного обхода:

```sh
.venv/bin/python collect.py --pilot --diagnose
```

`--pilot` использует первый запрос и первый регион из настроек, одну страницу, только ranked; отключает by_date и ценовые диапазоны. Каждый новый пилот по умолчанию создаёт отдельную папку `results/pilot-ДАТА-ВРЕМЯ`, поэтому основной progress.json не меняется. Дополнительно можно задать `--query "инъекционная гидроизоляция"`. Не запускайте пилоты в цикле при ограничении доступа.

При ошибке в подпапке `diagnostics` сохраняются JSON и PNG текущего окна. JSON содержит запрошенный и конечный URL, HTTP-статус (null, если ответ не получен), заголовок страницы, тип и текст ошибки, Retry-After, если он присутствовал. Retry-After записывается как диагностическое свидетельство; автоматического ожидания или повторного запроса по этому заголовку нет. Cookies и заголовки авторизации не сохраняются. Скриншот может содержать личные данные — проверьте его перед передачей.

С `--diagnose` при ошибке Chromium остаётся открытым для осмотра: посмотрите, написано ли там ограничение IP, проверка, капча или другая ошибка. Затем нажмите Enter в терминале — браузер закроется и появятся итоговые JSON/CSV. Скрипт не делает повторный запрос после осмотра. Прогресс и диагностические файлы сохраняются до ожидания Enter. В неинтерактивном терминале ожидание пропускается; headless с --diagnose запрещён.

При продолжении пилота явно укажите его папку: `--pilot --resume --output-dir results/pilot-ДАТА-ВРЕМЯ`. Живой доступ Авито этими тестами не подтверждён: проверки выполняются на локальных страницах и моделируемых ответах.
